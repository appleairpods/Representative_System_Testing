================================================================================
ЗАДАНИЕ 2. ТЕСТ-ПЛАН
Infinite Scroll (пагинация по 15 задач)
================================================================================

Продукт:        angular-todo-app
API:            JSONPlaceholder (https://jsonplaceholder.typicode.com/todos)
Фича:           При первой загрузке отображается 15 задач. При прокрутке
                списка вниз приложение делает новый запрос к API и подгружает
                следующие 15 задач.
Релиз:          Следующая неделя


================================================================================
1. ОБЛАСТЬ ТЕСТИРОВАНИЯ (SCOPE)
================================================================================

--------------------------------------------------------------------------------
1.1. ВКЛЮЧЕНО В ПРОВЕРКУ
--------------------------------------------------------------------------------

[1] Первичная загрузка
    - При открытии приложения отображается ровно 15 задач
      (или меньше, если в API меньше данных)

[2] Infinite scroll
    - Подгрузка следующей порции при достижении низа списка
    - Корректное добавление задач в конец списка без дублей

[3] API-запросы
    - Корректные параметры пагинации (_limit, _page / _start)
    - Правильный порядок и количество задач в ответе

[4] Состояния UI
    - Индикатор загрузки при первичной загрузке и при подгрузке
    - Отсутствие дублей при быстрой прокрутке
    - Корректное поведение при задержке ответа API (до 2 сек)

[5] Фильтры All / Active / Completed
    - Работа пагинации в каждом из фильтров
    - Корректное отображение подгруженных задач при переключении фильтров

[6] CRUD на загруженных данных
    - Создание, редактирование, удаление, отметка completed
      на задачах с первой и последующих страниц

[7] Граничные случаи
    - Последняя страница (менее 15 задач в ответе)
    - Пустой ответ API
    - Задержка ответа до 2 секунд

[8] Регрессия
    - Базовые сценарии без пагинации не сломаны
      (добавление, фильтры, редактирование, удаление)

================================================================================
2. УРОВНИ / ВИДЫ ТЕСТИРОВАНИЯ
================================================================================

--------------------------------------------------------------------------------
2.1. Функциональное тестирование
--------------------------------------------------------------------------------
Цель:     Проверить корректность работы пагинации
Примеры:  - При старте отображается 15 задач
          - При скролле вниз подгружается следующая порция по 15
          - Нет дублирования задач в списке

--------------------------------------------------------------------------------
2.2. Интеграционное тестирование (UI + API)
--------------------------------------------------------------------------------
Цель:     Проверить согласованность фронтенда и API
Примеры:  - Корректные параметры запросов к /todos
          - Обработка пустого и частичного ответа API
          - Соответствие данных в UI и в ответе сервера

--------------------------------------------------------------------------------
2.3. Регрессионное тестирование
--------------------------------------------------------------------------------
Цель:     Убедиться, что старый функционал не сломан
Примеры:  - Создание, редактирование, удаление задач
          - Фильтры All / Active / Completed
          - Валидация пустого названия при создании

--------------------------------------------------------------------------------
2.4. UI/UX тестирование
--------------------------------------------------------------------------------
Цель:     Проверить удобство и обратную связь для пользователя
Примеры:  - Наличие спиннера / скелетона при загрузке
          - Плавность скролла, отсутствие «прыжков» списка
          - Сообщение об ошибке при сбое API

--------------------------------------------------------------------------------
2.5. Граничное тестирование (Boundary)
--------------------------------------------------------------------------------
Цель:     Проверить поведение на границах значений
Примеры:  - 14-я и 16-я задача (граница первой страницы)
          - Последняя страница (< 15 задач в ответе)
          - 200-я задача (конец данных JSONPlaceholder)

--------------------------------------------------------------------------------
2.6. Негативное тестирование
--------------------------------------------------------------------------------
Цель:     Проверить обработку ошибок и сбоев
Примеры:  - Таймаут API, ответ 500
          - Блокировка сети при подгрузке второй страницы
          - Повторный запрос при ошибке

--------------------------------------------------------------------------------
2.7. Исследовательское тестирование
--------------------------------------------------------------------------------
Цель:     Найти неочевидные дефекты
Примеры:  - Быстрый скролл вниз-вверх
          - Смена фильтра во время загрузки
          - CRUD-операции во время подгрузки следующей страницы


================================================================================
3. РИСКИ И ПОКРЫТИЕ ТЕСТИРОВАНИЕМ
================================================================================

--------------------------------------------------------------------------------
R1. Дублирование задач при повторном срабатывании scroll
--------------------------------------------------------------------------------
Влияние:   Пользователь видит одни и те же задачи дважды
Покрытие:  Быстрая прокрутка вниз-вверх; проверка уникальности id в списке

--------------------------------------------------------------------------------
R2. Пропуск страницы (ошибка offset/limit)
--------------------------------------------------------------------------------
Влияние:   Часть задач не отображается
Покрытие:  Сверка общего количества с API; проверка порядка id
           на границах страниц (15->16, 30->31)

--------------------------------------------------------------------------------
R3. Множественные параллельные запросы при быстром скролле
--------------------------------------------------------------------------------
Влияние:   Лишняя нагрузка, дубли, гонки состояний
Покрытие:  Скролл до низа несколько раз подряд; в Network — не более
           1 активного запроса за раз

--------------------------------------------------------------------------------
R4. Задержка API до 2 секунд
--------------------------------------------------------------------------------
Влияние:   Пустой экран, повторные запросы, «зависший» спиннер
Покрытие:  Throttling в DevTools (Slow 3G); проверка индикатора загрузки
           и блокировки повторного запроса

--------------------------------------------------------------------------------
R5. Конфликт фильтров и пагинации
--------------------------------------------------------------------------------
Влияние:   Неверный набор задач в Active / Completed
Покрытие:  Переключение фильтров до и после подгрузки;
           подсчёт: active + completed = all

--------------------------------------------------------------------------------
R6. CRUD во время подгрузки
--------------------------------------------------------------------------------
Влияние:   Потеря или дублирование изменений
Покрытие:  Создать задачу -> прокрутить; отметить completed
           на 1-й и 20-й задаче

--------------------------------------------------------------------------------
R7. Последняя страница
--------------------------------------------------------------------------------
Влияние:   Бесконечные запросы к API
Покрытие:  Прокрутка до конца (200 задач); после последней порции
           новых запросов нет

--------------------------------------------------------------------------------
R8. Ошибка API при подгрузке
--------------------------------------------------------------------------------
Влияние:   Список обрывается без сообщения пользователю
Покрытие:  Блокировка сети на 2-й странице; ожидаем сообщение
           об ошибке или кнопку Retry

--------------------------------------------------------------------------------
R9. Смена фильтра во время загрузки
--------------------------------------------------------------------------------
Влияние:   Смешение данных разных фильтров
Покрытие:  Active -> скролл -> во время загрузки переключить на Completed

--------------------------------------------------------------------------------
R10. Регрессия базового CRUD
--------------------------------------------------------------------------------
Влияние:   Сломалось создание, редактирование, удаление
Покрытие:  Smoke: add, edit, delete, toggle на 1-й и после подгрузки
           2-й страницы

4. КРИТЕРИИ ГОТОВНОСТИ (DEFINITION OF DONE)
================================================================================

Фичу можно отдавать в релиз, если выполнены ВСЕ пункты ниже.

--------------------------------------------------------------------------------
4.1. Функциональность
--------------------------------------------------------------------------------
[ ] При первой загрузке отображается не более 15 задач
[ ] При прокрутке до низа подгружается следующая порция (до 15 задач)
[ ] Нет дублей задач по id во всём загруженном списке
[ ] На последней странице подгрузка прекращается, лишних запросов нет
[ ] Фильтры All / Active / Completed работают с подгруженными данными
[ ] CRUD (создание, редактирование, удаление, complete) работает
    на задачах с любой подгруженной страницы

--------------------------------------------------------------------------------
4.2. UI/UX
--------------------------------------------------------------------------------
[ ] Есть индикатор загрузки при первичной загрузке и при подгрузке
[ ] При ошибке API показывается понятное сообщение (не пустой экран)
[ ] Список не «прыгает» при добавлении новых задач внизу

--------------------------------------------------------------------------------
4.3. API / технические требования
--------------------------------------------------------------------------------
[ ] Запросы содержат корректные параметры пагинации
[ ] При задержке до 2 сек UI остаётся отзывчивым,
    нет дублирующих запросов
[ ] Нет критических и major дефектов по пагинации в открытом виде

--------------------------------------------------------------------------------
4.4. Регрессия
--------------------------------------------------------------------------------
[ ] Smoke-набор базовых сценариев (add, filter, edit, delete, complete)
    пройден без блокеров

--------------------------------------------------------------------------------
4.5. Известные ограничения (НЕ блокируют релиз)
--------------------------------------------------------------------------------
[-] Данные не сохраняются после reload (ограничение JSONPlaceholder)
[-] Minor UI-дефекты вне области пагинации (если согласованы с командой)
